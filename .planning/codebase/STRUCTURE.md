## Directory Purposes

**`api/v1/`:**
- Purpose: Go type definitions for all three CRDs (`Backup`, `Database`, `Storage`)
- Contains: `*_types.go` files with Spec/Status structs + Kubebuilder markers; `groupversion_info.go` registers `gobackup.io/v1alpha1`; `zz_generated.deepcopy.go` is auto-generated (do not edit)
- Key files: `api/v1/backup_types.go`, `api/v1/database_types.go`, `api/v1/storage_types.go`

**`internal/controller/`:**
- Purpose: All reconciliation logic; kept `internal/` to prevent external import
- Contains: Single `backup_controller.go` with the `BackupReconciler` struct and all its methods; `suite_test.go` for controller integration tests via envtest
- Key files: `internal/controller/backup_controller.go`

**`pkg/k8sutil/`:**
- Purpose: Kubernetes API helpers that the controller delegates to for raw API operations
- Contains: `K8s` struct (wraps clientset + dynamic client); Secret generation/resolution; CRD dynamic fetch; Job deletion
- Key files: `pkg/k8sutil/secret.go` (most complex — builds `gobackup.yml`), `pkg/k8sutil/crd.go`

**`cmd/`:**
- Purpose: Binary entry point; wires everything together at startup
- Contains: Single `main.go`
- Key files: `cmd/main.go`

**`config/`:**
- Purpose: Kustomize-based deployment manifests; source of truth for CRD YAML and RBAC
- Contains: CRD YAML in `config/crd/bases/` (generated by `make manifests`); RBAC generated from `//+kubebuilder:rbac` markers; sample CRs in `config/samples/`
- Key files: `config/crd/bases/gobackup.io_backups.yaml`, `config/rbac/role.yaml`, `config/manager/manager.yaml`

**`charts/gobackup-operator/`:**
- Purpose: Helm chart for cluster installation; the recommended production deployment method
- Contains: Deployment, RBAC, ServiceMonitor templates; CRDs in `charts/gobackup-operator/crds/` (must be manually synced from `config/crd/bases/` — see `.claude/memory/`)
- Key files: `charts/gobackup-operator/values.yaml` (image, resources, leaderElection, backupJob.image)

**`test/e2e/`:**
- Purpose: End-to-end smoke tests against a live cluster
- Contains: `e2e_test.sh` (bash); sample CR manifests under `manifests/`

**`hack/`:**
- Purpose: Developer convenience scripts; not part of CI pipeline
- Contains: operator smoke test, CRD validation, boilerplate header

## Key File Locations

**Entry Points:**
- `cmd/main.go`: Operator binary — manager setup, scheme registration, reconciler wiring

**CRD Types:**
- `api/v1/backup_types.go`: `BackupSpec`, `BackupStatus`, `BackupSchedule`, `DatabaseRef`, `StorageRef`, `BackupRunStatus`
- `api/v1/database_types.go`: `DatabaseSpec`, `DatabaseConfig` (postgresql/mysql/redis/mongodb/mssql/influxdb/etcd)
- `api/v1/storage_types.go`: `StorageSpec`, `StorageConfig` (s3/gcs/azure/sftp/ftp/webdav/minio/…)

**Controller:**
- `internal/controller/backup_controller.go`: `BackupReconciler`, `Reconcile`, `handleBackupCreate`, `handleBackupUpdate`, `reconcileJobStatus`, `createCronJob`, `buildJobTemplate`, `triggerManualBackupJob`, `findBackupForJob`

**Kubernetes Utilities:**
- `pkg/k8sutil/secret.go`: `CreateSecret` — the most complex function; orchestrates CRD lookup, SecretRef resolution, YAML marshalling
- `pkg/k8sutil/crd.go`: `GetCRD` — dynamic client fetch for Database/Storage CRD instances
- `pkg/k8sutil/k8sutil.go`: `NewClient`, `NewDynamicClient` — client construction (in-cluster then kubeconfig fallback)

**Configuration:**
- `config/crd/bases/gobackup.io_backups.yaml`: Generated CRD manifest for `Backup`
- `config/rbac/role.yaml`: Generated RBAC from kubebuilder markers
- `charts/gobackup-operator/values.yaml`: Helm deployment configuration

**Testing:**
- `internal/controller/suite_test.go`: envtest bootstrap for controller integration tests
- `test/e2e/e2e_test.sh`: Shell-based E2E runner

## Naming Conventions

**Files:**
- CRD type files: `<kind>_types.go` (e.g., `backup_types.go`, `database_types.go`)
- Controller files: `<kind>_controller.go` (e.g., `backup_controller.go`)
- Generated deepcopy: `zz_generated.deepcopy.go` (never edit manually)
- Test suites: `suite_test.go` for envtest bootstrap; feature tests would follow `<kind>_controller_test.go`
- Kubernetes manifests: `<group>.<domain>_<plural>.yaml` (e.g., `gobackup.io_backups.yaml`)

**Directories:**
- API types: `api/<version>/` (currently only `v1`)
- Private logic: `internal/<component>/`
- Exported helpers: `pkg/<package>/`

**Go symbols:**
- Reconciler struct: `<Kind>Reconciler` (e.g., `BackupReconciler`)
- Spec type: `<Kind>Spec` (e.g., `BackupSpec`, `DatabaseSpec`)
- Status type: `<Kind>Status` (e.g., `BackupStatus`)
- List type: `<Kind>List` (e.g., `BackupList`)
- Kubebuilder RBAC markers: `//+kubebuilder:rbac:groups=<group>,resources=<plural>,verbs=<verbs>`
- Short names: `//+kubebuilder:resource:shortName=<name>` (backup, db, storage)

**JSON tags:**
- CRD fields use camelCase JSON tags (e.g., `databaseRefs`, `storageRefs`)
- gobackup.yml config fields use snake_case internally; the `CreateSecret` function converts between them explicitly (see `pkg/k8sutil/secret.go:91-102`, `pkg/k8sutil/secret.go:149-165`)
- `*_ref` suffix convention identifies `corev1.SecretKeySelector` fields (resolved at reconcile time)

## Where to Add New Code

**New CRD kind (e.g., a second database type):**
- Type definition: `api/v1/<kind>_types.go` — follow `database_types.go` as template
- Register in: `api/v1/groupversion_info.go` (add `SchemeBuilder.Register`)
- Auto-generate deepcopy: run `make generate`
- Auto-generate CRD YAML: run `make manifests` → updates `config/crd/bases/`
- Hand-sync CRD to Helm: copy updated YAML into `charts/gobackup-operator/crds/`

**New reconcile logic (e.g., a second controller for a new CRD):**
- Implementation: `internal/controller/<kind>_controller.go`
- Tests: `internal/controller/<kind>_controller_test.go` alongside `suite_test.go`
- Register in: `cmd/main.go` (add `SetupWithManager` call)

**New Kubernetes utility helper:**
- Location: `pkg/k8sutil/<topic>.go` (follow pattern of `crd.go`, `secret.go`)
- Add method to `K8s` struct or as standalone function in the package

**New Backup spec field:**
- Add field to `BackupSpec` in `api/v1/backup_types.go`
- Update `CreateSecret` in `pkg/k8sutil/secret.go` to include the field in `gobackup.yml`
- Run `make generate && make manifests`
- Hand-sync `charts/gobackup-operator/crds/gobackup.io_backups.yaml`

**New storage or database backend:**
- No Go code needed if the backend already maps to the generic `StorageConfig`/`DatabaseConfig`
- Add `type` enum value to `//+kubebuilder:validation:Enum=...` marker in the appropriate `_types.go`
- Add any backend-specific fields to `StorageConfig` or `DatabaseConfig` with CEL validation markers
- Add sample manifests under `config/samples/storage/` or `config/samples/database/`

## Special Directories

**`bin/k8s/`:**
- Purpose: envtest Kubernetes API server binaries for integration tests
- Generated: Yes (downloaded by `make envtest`)
- Committed: No (in `.gitignore`)

**`build/bin/`:**
- Purpose: Locally installed build tools (`controller-gen`, `golangci-lint`)
- Generated: Yes (by Makefile targets)
- Committed: No

**`config/crd/bases/`:**
- Purpose: Source-of-truth CRD YAML generated from Go type markers
- Generated: Yes (by `make manifests` via `controller-gen`)
- Committed: Yes

**`charts/gobackup-operator/crds/`:**
- Purpose: CRD YAML embedded in Helm chart for installation
- Generated: No — must be manually copied from `config/crd/bases/` after `make manifests`
- Committed: Yes
- Warning: See `.claude/memory/chart-crds-not-autosynced.md` — `make manifests` skips this directory; hand-sync or Helm prunes new fields

**`api/v1/zz_generated.deepcopy.go`:**
- Purpose: Auto-generated `DeepCopyObject` implementations required by controller-runtime
- Generated: Yes (by `make generate` via `controller-gen`)
- Committed: Yes (never edit manually)
